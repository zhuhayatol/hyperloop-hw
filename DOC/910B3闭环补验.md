# 910B3 闭环补验

本轮验收用同一张昇腾 910B3、固定 SGLang `fdebc938`、Qwen2.5-0.5B-Instruct BF16 和四组 Prefill／Decode 请求。服务计时前先与独立参考逐 token 核对，正式测速关闭 Profile，使用两轮预热和三轮计时。沿用最低 5% 吞吐收益、2% 噪声线以及 TTFT P95、TPOT P95 各 10% 的回归上限。候选的裁决与流程能否跑通分别记录。

## 联合会话与 Forge 恢复

联合会话 `C` 从原版 SGLang 重新采参考输出、基线和 Profile。真机 Prefill 和 Decode 分别记录 2,138 和 2,109 条计算内核事件。Coordinator 把固定任务与采集摘要交给 Orchestration。Orchestration 委派 Specialist，Specialist 输出 Qwen2 的单行补丁，将 `qkv.split` 的尺寸参数由列表改成元组。Intent Router 登记提案并交 Critic。Critic 同意试测，同时指出改动影响小，预计很难跨过 5% 性能门槛。Dispatcher 随后派发 `integrate_patch`。三个角色在这次交接中分别消耗 46、178、86 个输出 token，实际请求和回复逐条留存。

独立评测用不同的 SGLang 进程分别加载候选和父版。两侧四组输出完全一致，各测三轮。补丁的吞吐从父版的 36.69 降至 30.57 tok/s，TTFT P95 从 215.76 升至 258.99 ms。程序按门槛给出 `REVERT / ttft_regression`，Coordinator 保留原版并进入算子阶段。

当 Forge Worker 启动实际 `bisheng` 编译、尚未生成第一个二进制或动作回执时，验收脚本中断了本会话的 Coordinator，随后运行正常的 `resume`。恢复流程清理中断任务 `task-0005` 的进程租约，写入恢复记录，并派出携带 `retry_of=task-0005` 的 `task-0006`。

重试完成两个 BF16 形状的编译及 CPU 参考校验。`2 × 9728` 和 `512 × 9728` 各记录 25 个设备计时样本，候选两个形状均较慢。Forge 交回算子源码补丁，独立评测装进 SGLang。从正式校验请求产生的调用标记核对到同一次服务的进程和 `activation.py` 摘要，确认实际命中。服务候选、父版均通过四组逐 token 校验，各测三轮。候选吞吐从 36.36 降至 31.59 tok/s，TTFT P95 从 216.42 升至 250.57 ms，裁决 `REVERT / ttft_regression`。旧任务的恢复回执显示租约已释放，剩余进程列表为空。

算子任务结束后，Coordinator 自动派发 `conc_sweep`，取得并发 1、2 的结果。由于两个候选已经回退，每档比较的是两次独立启动的原版。结果存回 Session 后，Coordinator 根据本轮上限进入 CLOSE，写完记录后进入 DONE。两档中位吞吐的自然差异为 +3.49% 和 +1.29%，只代表本次同版本重复测量的差异。

## Recipe 历史参数复用

新会话用正常 `--recipe` 入口读入历史会话留下的 `final.json`。目标环境、模型和请求指纹匹配后，Session 写入 `recipe_retrieved`。Coordinator 把历史的 `chunked_prefill_size=768` 放进 DeepSeek 的 `recipe_suggestions`。Orchestration 的真实回复提交 `recipe-cps-768`，明确引用历史 Recipe，随后由正常路由派给 Explorer。DeepSeek 的首次调用为 HTTP 200，输入 1,312 token，输出 131 token。

## Enablement 自动诊断和修复

在固定请求下，用 `chunked_prefill_size=513`、`page_size=128` 启动 SGLang，取得真实的整除断言和失败回执。Coordinator 登记启动诊断任务，Specialist 从已核对的服务日志提取断言和实参后交给 DeepSeek。请求里包含故障条件和可改参数。DeepSeek 返回 `513 → 512`，解释 512 是最接近 513 的正数且能被 128 整除。这次真实调用为 HTTP 200，输入 409 token，输出 87 token。程序验证修复参数合法后，Dispatcher 派了单独的修复启动和复测任务。

修复版成功启动。四组请求逐 token 匹配独立原版参考，三轮吞吐中位数为 105.26 tok/s，TTFT P95 为 190.39 ms。Coordinator 将首个可运行的 `task-0002-startup-repair` 记作有效基线，并保留 513 启动失败的日志。闭环证据适用于本次核验的分块整除故障。

## 模型 forward 独立计时

评测端分别启动参考服务、常规在线计时服务和 forward 计时服务。计时服务在真正的 `Qwen2ForCausalLM.forward` 前后记录 NPU Event，从模型接收 token 和位置张量开始，到该次调用给出 logits 为止。HTTP 请求只驱动同样的 batch，调度、通信和 HTTP 响应位于边界外。计时期间关闭图回放和 Profile。服务的源码文件、模型、dtype 和 worker PID 都由回执核对。

首次输出核对和三轮实际采样均覆盖四组请求，每次输出都与独立参考逐 token 一致。共记录 159 次真实模型调用，Prefill 15 次、中位数 46.24 ms，Decode 144 次、中位数 45.72 ms。原始记录保留每次调用的阶段、输入形状和耗时。单算子设备计时、模型 forward 和整套 SGLang 服务的计时各有独立记录。

## 如何读本轮结果

- **六项闭环都取得了真机证据。** 其中整栈复测用了独立合成候选，CLOSE 缺件测试只操作隔离副本，Forge 中断发生在实际编译期间。
- **性能通过的是分块 768。** 框架、Forge 和双补丁候选均通过正确性校验，并按锁定的性能门槛回退。GEAK 已在此前的 910B3 会话完成 FIA 候选交付与独立复测。当前证据覆盖使用的 Qwen2 负载、FIA 路线和 SwiGLU 形状。双卡 910B2 的独立验收另行记录。
- **实际 DeepSeek 用量为 6 次调用、8,467 token，其中输出 681 token。** 框架补丁、Recipe 两次回复及启动修复均留存角色原始输出。算子构建、独立测量和版本裁决由各自的执行程序产生回执。
- **验证过程中的问题都保留了记录。** 独立整栈复测用于验证两个已回退补丁的同次加载。CLOSE 副本的历史 Profile 原件留在原会话，归档时到源目录重算摘要。新真机路径的原始记录和旧模拟场景在回放中分别保留各自来源。

动态图新增六个真机场景、253 步。浏览器逐步核对箭头标签、自动播放、暂停、跳转和证据入口。报告的 28 个链接已核对。本地测试运行 132 项，131 项通过，1 项因 Windows 符号链接权限跳过。最后一次检查确认 910B3 没有残留进程。
