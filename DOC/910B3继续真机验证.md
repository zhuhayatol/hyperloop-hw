## 框架补丁装回 SGLang

在受保护的工作目录用 `edc47a2` 完成第二个真机会话。Orchestration 委派一行源码修改。Specialist 交回 `qwen2-qkv-split-tuple`，将 `qwen2.py` 中 `qkv.split` 的固定长度列表换成元组。Critic 对 `proposal-0001` 返回 `approve` 后，Router 才登记 Integrate Patch。这个候选用于验证真实补丁加载链路。

执行器在独立源码副本应用补丁。SGLang 启动时记录实际加载的 `qwen2.py` 路径、进程 ID 和 SHA-256。Evaluator 随后校验候选和另起的父版，四组输出均逐 token 一致。两侧完成各 3 轮服务计时和清理。

补丁的配对吞吐为 109.22 对 104.01 tok/s（+5.01%），按锁定门槛得到 `KEEP`。候选相对本会话原始基线的吞吐为 −0.51%，两侧首轮均在约 26 tok/s。这轮已验证加载和评测闭环，现有样本不足以把稳定的性能收益归因给元组改动。

## 预编译 Attention 路径对照

固定分块 512 和四组请求，在 910B3 上对照 `ASCEND_USE_FIA=0/1`。两侧逐 token 校验均通过。开启 FIA 后，吞吐从 108.83 降至 104.45 tok/s（−4.02%），TTFT P95 从 186.29 升至 216.06 ms（+15.98%），裁决 `REVERT / ttft_regression`。

随后两侧各用两个长请求、只生成一个 token，单独采集 Prefill。默认侧有 72 条 FlashAttention 事件关联到 `ascend_backend.py:1479`。开启 FIA 后，有 96 条 FusedInferAttentionScore 事件关联到 `ascend_backend.py:1386`，该窗口未出现前者。两侧各有 24 条同名 FIA 事件未定位，因此原脚本按名称判定的结果仍是 `inconclusive`。源码调用点和原始 trace 均可复核。
