# 运行与复核

## 用任务文件和启动配置开始一轮优化

在已载入设备环境的 Hyperloop 源码目录执行。以下两个文件是本轮 910B3 保护环境的示例。

```bash
python -m hyperloop start --task configs/task.910b3.optimization.md --config configs/start.910b3.protected.yaml
```

Markdown 写优化目标，YAML 选环境、搜索轮数和预算。入口自动冻结输入、检查设备、准备原版基线并创建会话。运行日志同时输出到终端和 `console.log`。`最新说明.md` 显示最后确认的进度，`report.md` 可追到提案、测量和裁决使用的证据。运行目录在终端输出中给出。

910B3 的保护环境由现有启动封装载入。本次实机部署可用下面这一条命令调用相同入口。路径指向部署在该卡上的代码及配套配置，启动过程从同一个 `start` 接管。

```bash
base=/opt/hyperloop-910b3-trial
repo="$base/autonomous-src-reuse"
sudo -n bash "$base/closure-inputs/protected-python.sh" "$repo" -m hyperloop start --task "$repo/configs/task.910b3.optimization.md" --config "$repo/configs/start.910b3.protected.yaml"
```

### 选择原始基线

`baseline_mode` 写在启动 YAML 的顶层。默认值 `measure` 会测量本轮原始基线，真机也会独立采集原版 Reference。想复用时，将该字段改为下面的值，再执行同一条 `start` 命令。

```yaml
baseline_mode: reuse_latest
```

项目在 `session_root` 下查找同一运行模式中的原始基线，核对目标与实际运行时、原版 SGLang 执行栈、模型与 tokenizer、完整负载及测量和评估规则。通过证据校验的基线按实际测量时间选最新一份，真机沿用同一基线的 Reference。若找不到匹配项，启动会停止并给出原因。将 `baseline_mode` 设为 `measure` 后重新启动，即可建立新基线。

启用了 Profile 时优先复用同一来源会话中验证通过的 Profile，缺失或校验失败时重新采集。候选配对测试和最终验收配对复测均在本轮执行。

报告的「历史基线来源」记录来源会话、原始测量时间和证据摘要。要跨机器重启复用，需要把原会话和原始证据保存在持久化的 `session_root` 中。

遇到可恢复中断时，用同一设备环境执行 `python -m hyperloop resume 会话目录`。日志保留失败及恢复回执。已经完成的会话可以通过 `status` 查看停止原因、接受版和独立目标验收。 [输入与交付设计](任务输入、运行观察与交付设计.md)

## 复现此前 910B3 会话的旧入口

以下入口用于复现此前的会话。新的任务文件和启动配置使用前面的 `start` 命令。

```bash
bash /opt/hyperloop-910b3-trial/start-910b3.sh
```

入口复用这张卡上已部署的 Hyperloop、SGLang、评测负载和 DeepSeek 配置。它从分块 512 建原始基线，保留历史接受的 768 作为提案参考。Agent 根据本轮 Profile 决定提调参或框架补丁，算子阶段沿用现有 Forge。参数、补丁和组合的收益均按本次运行的冻结设置核对。会话目录和报告路径会打印在终端。

加 `--check` 可以检查旧部署版本、输入和设备空闲状态。这版启动脚本的自动停止条件只检查吞吐，需在旧报告中另外核对同一接受版的 TTFT P95。 [此前真机结果](910B3闭环补验.md)

### 复现旧会话时配置 JSON

以下命令在 910B3 的 Linux 远程终端执行，使用卡上已部署的保护环境。这条旧入口读取自定义 JSON。

**准备工作目录。** 如果已有完整的配置文件，将 `job` 设为该目录的绝对路径即可。第一次可以复制已验证的联合会话配置作为模板。

```bash
base=/opt/hyperloop-910b3-trial
job=$(mktemp -d /mnt/workspace/hl-job.XXXXXX)
cp "$base/closure-inputs/combined-task.json" "$job/task.json"
cp "$base/closure-inputs/combined-target.json" "$job/target.json"
cp "$base/closure-inputs/excerpts.json" "$job/excerpts.json"
printf '{}\n' > "$job/scenario.json"
printf '配置目录 %s\n' "$job"
```

**填入你的任务。** 用 VS Code 打开上面打印的目录，在完整的 `task.json` 中替换旧模板的 `agent_objective`。这里可以写一行中文，最多 500 字符。例如填入「比较调参、框架补丁和算子，按本轮 Profile 选先查的瓶颈。最终同一版本相对原始基线吞吐提高至少 15%，TTFT P95 降低至少 15%，输出逐 token 一致。」这段话会作为 Agent 的任务说明。

| 想设什么 | 在哪里改 |
| --- | --- |
| 主负载并发 2，预热 2 轮，计时 3 轮 | `task.json` 的 `workload.concurrency`、`rules.warmup`、`rules.repeats` |
| 最多 3 个循环，每轮最多 2 次编排，调度预算 45 | `task.json` 的 `settings.max_cycles`、`settings.max_turns_per_cycle`、`settings.budget` |
| 采集 Profile、扫并发 1／2／4、走 Forge | `task.json` 中设 `settings.profile_enabled` 和 `settings.sweep_enabled` 为 `true`，`settings.sweep_concurrency` 为 `[1, 2, 4]`，`settings.kernel_backend` 为 `forge` |
| 选择原始分块、模型路径和可改的源码范围 | `target.json` 的 `sglang.server_args`、`sglang.model_path` 和 `sglang.allowed_source_paths`。`excerpts.json` 提供允许交给 Agent 的真实源码片段。换模型还要更新任务中的 `model` 和目标的模型与 tokenizer 摘要 |

**启动会话。** 在同一个终端执行下面的命令。若换了终端，先把 `job` 设为前面打印的配置目录。命令先核对设备空闲，复制本次输入，再采集原版参考输出并开始优化。结果会放进新的 `/opt/h15-XXXXXX` 目录。

```bash
sudo -n bash -s -- "$job" <<'BASH'
set -eo pipefail
job=$1
base=/opt/hyperloop-910b3-trial
repo="$base/closure-forward"
runner="$base/closure-inputs/protected-python.sh"
key_file=/home/developer/.config/hyperloop/deepseek.key

run_python() { bash "$runner" "$repo" "$@"; }
if [[ ! -s $key_file || $(stat -c %a -- "$key_file") != 600 ]]; then
    printf 'DeepSeek Key 文件缺失或权限不是 0600：%s\n' "$key_file" >&2
    exit 1
fi
npu=$(run_python -c 'import subprocess; print(subprocess.check_output(["npu-smi", "info"], text=True), end="")')
printf '%s\n' "$npu"
grep -q '910B3' <<<"$npu"
grep -q 'No running processes found' <<<"$npu"

out=$(mktemp -d /opt/h15-XXXXXX)
chmod 755 "$out"
inputs="$out/inputs"
mkdir "$inputs"
cp -- "$job"/{task,target,scenario,excerpts}.json "$inputs/"
printf '%s\n' "$npu" > "$out/npu-before.txt"
git -c safe.directory="$repo" -C "$repo" rev-parse HEAD > "$out/hyperloop-commit.txt"
export TRITON_CACHE_DIR="$out/tool-cache"
exec > >(tee "$out/console.log") 2>&1
printf '会话目录 %s/real/h15\n' "$out"

run_python -m hyperloop capture-reference \
  --task "$inputs/task.json" --target "$inputs/target.json" \
  --output "$out/reference"

(
  set +x
  export DEEPSEEK_API_KEY="$(< "$key_file")"
  run_python -m hyperloop run \
    --task "$inputs/task.json" --target "$inputs/target.json" \
    --scenario "$inputs/scenario.json" \
    --reference "$out/reference/reference.json" \
    --reference-receipt "$out/reference/capture.json" \
    --agent-provider deepseek --agent-source-excerpts "$inputs/excerpts.json" \
    --session-root "$out" --session-id h15
) | tee "$out/session.run.json"
printf '报告 %s/real/h15/report.md\n' "$out"
BASH
```

自定义任务进入 Agent 回合后，实测仍以被冻结的原版、负载和规则为准。当前的双指标目标在报告中对照 `comparison.over_original` 核验。若重新修改负载、模型或基线，下次启动会采集与新任务匹配的参考输出。

## 运行一次完整模拟

从 `Hyperloop/` 目录执行。

```text
python -m pip install -e .
python -m hyperloop run --task configs/task.simulated.json --target configs/target.910b3.simulated.json --reference fixtures/reference.simulated.json --scenario fixtures/scenario.simulated.json --session-root sessions --session-id forge-910b3
```

该样例固定长输入短输出、短输入长输出两组请求，重复计时三次。Orchestration 先直委 Explore，再派 Specialist 提交框架补丁，Critic 按提案 ID 评审。然后阶段机记录算子阶段、成对扫描与回环。第二轮用尽固定响应后收束流程。示例资料给定的吞吐中位数为 100、110、115、122、123 tok/s。最后的 123 比父版 122 高约 0.82%，低于锁定的 2% 门槛。

本地算子阶段演练 GEAK 式服务方案交付和 Forge 式算子补丁交付。设备内核、模型 forward、在线服务三类计时分开归档。Profile 使用模拟采集；上游可选的 Roofline、专项 GEMM 调优与 Fusion 后端留在具体运行适配阶段。

同一任务、参考与 Agent 场景也可搭配双 rank 目标，或在 Session 创建时选择另一条算子路线。下面同时演示这两项变更。

```text
python -m hyperloop run --task configs/task.simulated.json --target configs/target.910b2-tp2.simulated.json --reference fixtures/reference.simulated.json --scenario fixtures/scenario.simulated.json --session-root sessions --session-id geak-910b2 --kernel-backend geak
```

双 rank 目标记录 rank 0 和 rank 1 的模拟 Profile。每次 `run` 使用新的 Session ID。中断后沿用生成的 Session 路径和冻结输入。

## 查看、恢复和独立复测

```text
python -m hyperloop status sessions/simulated/forge-910b3
python -m hyperloop resume sessions/simulated/forge-910b3
python -m hyperloop report sessions/simulated/forge-910b3
python -m hyperloop reproduce sessions/simulated/forge-910b3 R03
```

- `status` 从完整的落盘事件读取阶段、任务状态、已接受版本和候选裁决。
- `run` 和 `resume` 支持 `--max-steps N`。用它在若干调度步骤后暂停，再从同一目录恢复。
- `report` 从相同的事件和证据重建 `summary.json`、`report.md` 和可离线打开的 `report.html`。报告可查看角色与任务交接、验收、Profile 和原始证据引用。
- `reproduce` 使用该候选和父版的冻结规格独立复测。查看返回的复测证据位置和裁决。复测证据单独留存，原 Session 的版本结算保留。

Session 根目录下的 `manifest.json` 保存输入快照，`events.jsonl` 是事件记录，`state.json` 是可重建缓存。报告通过证据索引指向各次运行的原始文件。模拟数据可核对流程与口径，真机收益按真实环境独立建立基线。

查看 `rounds/<候选>/evidence_bundle.json` 可定位父版、原始基线、参考输出和指标数据。每次派发的完整回执位于 `evidence/actions/`，独立 Critic 的裁决依据位于 `evidence/decisions/`。 `profile/` 保存各 rank 采集索引，`sweep/` 保存并发点对照与跳过原因。

## 逐次查看验证的交接图

打开 `report.html` 的「验证交接图」，选择任务，再展开其中一次评测。每行从左到右看发送模块、发送的内容、接收模块及其操作。实际返回消息会另画一行。候选验收详情也能跳到该候选的图。[打开 GEAK 双 rank 模拟示例](../.runs/acceptance-base-v0.1-release/simulated/geak-tp2/report.html#validation)

- **会话事件**可跳到任务登记、派发、结果回收和独立 Critic 裁决。框架正式补丁另有提案和预审节点。
- **执行记录**加载本次 `evaluation/<attempt_id>/validation_flow.json` 保存的实际交接。服务、算子及 forward 分开列，重复测速标出轮次。失败后的跳过也有状态。
- **证据还原**用于已完成的早期 Session。原始文件能支持哪一步就显示哪一步，并链接相应文件。

并发扫描按并发点和原始版／接受版展示。运行 `reproduce` 会留下独立复测回执，并刷新交接图。候选的历史裁决和原事件日志沿用原记录。

## 在新 Session 参考旧配方

完成的 Session 若写出了 `evidence/recipes/final.json`，可在新一轮运行时通过 `--recipe` 导入。

```text
python -m hyperloop run --task configs/task.simulated.json --target configs/target.910b3.simulated.json --reference fixtures/reference.simulated.json --scenario fixtures/scenario.simulated.json --session-root sessions --session-id forge-910b3-recipe --recipe sessions/simulated/forge-910b3/evidence/recipes/final.json
```

导入时核对来源会话已关闭、配方是该会话登记的最终产物、证据摘要对应原始文件。新 Session 在预检后核对模型、tokenizer、工作负载、目标设备与实际环境。匹配的参数作为 Agent 回合参考，仍由新 Session 建立原始基线、提交候选并独立校验和计时。两套卡型与 TP 配置分别验收。

## 本地验收

```text
python -m unittest discover -s tests -v
```

验收覆盖问题输入、权限和直接委派、候选预审、租约释放、独立证据门、两条算子路径、成对扫描和回环恢复。启用故障路径的测试可使用同一场景中的 `base-unavailable` 初始版本，复验后锚定首个能运行的 `base-fixed`。
