## 输入和判断

| 输入 | 内容 |
| --- | --- |
| 服务 | 910B3 单卡，TP=1，BF16，Qwen2.5-0.5B-Instruct。冻结 SGLang 提交、模型和 tokenizer 文件摘要。 |
| 请求 | 固定四个 token ID 序列。两个长输入分别为 768、640 token，各生成 16 token。两个短输入分别为 64、96 token，各生成 32 token。并发 2，贪心解码。 |
| 改动 | 原版预填充分块为 512，R01 改为 256。候选意图来自固定输入，SGLang 启停、推理、正确性和计时都在真机上执行。 |
| 接受条件 | 与原版独立采集的 token ID 逐个相同。候选和父版各热身后测 3 轮。吞吐至少增加 5%，首 token 延迟和后续单 token 时延各最多增加 10%。 |

1. 单独启动原版采集参考，退出后另起原版服务建立基线。这样参考与正式评测有各自的服务身份。
2. Explore 只改变分块大小。Evaluator 检查新服务实际加载的值，逐个对比输出，通过后根据流式 `/generate` 请求计算吞吐与延迟。候选与父版各自启动并测量。
3. 裁决程序读取原始记录重新计算，按锁定规则决定去留。表里的吞吐和延迟为三轮中位数。延迟在每轮从请求计算 P95。

## 真机结果

固定请求的四组输出 token 在基线、候选和配对父版均通过校验。性能裁决比较的是另外启动的配对父版和 R01。

| 指标 | 原始基线 512 | 配对父版 512 | R01 候选 256 | R01 相对父版 |
| --- | ---: | ---: | ---: | ---: |
| 吞吐（tok/s） | 96.24 | 96.77 | 83.40 | −13.81% |
| 首 token 延迟 P95（ms） | 201.77 | 202.45 | 374.39 | +84.93% |
| 后续单 token 延迟 P95（ms） | 15.40 | 15.58 | 22.53 | +44.63% |

**R01 退回，保留分块 512。** 首 token 延迟回归超过锁定的 10% 上限，独立裁决记录为 `ttft_regression`。这轮验证了单卡服务、正确性、实测采样和版本裁决。Profile 和算子路线在这组设置中关闭。双卡验收另立 Session。

原始基线首轮出现明显波动，吞吐为 25.45 tok/s，首 token 延迟为 2956.26 ms。该轮原样保留，基线表按预定的三轮中位数呈现。R01 的裁决依据是同一任务里重新启动的父版。会话结束后 NPU 查询无运行进程。本地在测试提交上运行 94 项用例，93 项通过，1 项因 Windows 符号链接权限跳过。
