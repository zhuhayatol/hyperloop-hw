# 910B3 单卡部署与初验

2026-11-24（北京时间）。本轮用同一张 910B3 上的原版 SGLang 单独采参考输出，再用 Hyperloop 复测基线和一个调参候选。判断依据是实际加载的参数、服务返回的 token 与逐请求计时。[初验信号流](910B3初验信号流.html)

## 迁移和部署记录

| 步骤 | 记录 |
| --- | --- |
| 核对连接 | 复用 VS Code 的 CANNLab SSH。登录 shell 可识别单张健康的 910B3，HBM 为 64 GiB。预检时卡空闲。 |
| 核对环境 | ARM64、CANN 9.0.0、Python 3.11.4、Torch NPU 2.10.0。复用现有的 SGLang 0.5.16、Qwen2.5-0.5B-Instruct 和 ATB、自定义算子环境。SGLang 源码标记为 `fdebc938f7f4d16fe6b9f55dcd9a767cf0899ea1`。 |
| 迁移源码 | 在 `/mnt/workspace/src/hyperloop` 独立克隆 `origin/main`。克隆时远端提交为 `ae13f5e`，底稿标签 `base-v0.1` 指向 `c9d10c1`。本地适配提交通过同一 `main` 同步。 |
| 运行 | `bash -lc 'cd /mnt/workspace/src/hyperloop && bash scripts/run-910b3-initial.sh .runs/910b3-initial/新目录名'`。脚本加载现有运行环境、存 Git 版本和卡状态，再分别执行参考采集和正式会话。 |

## 输入和判断

| 输入 | 内容 |
| --- | --- |
| 服务 | 910B3 单卡，TP=1，BF16，Qwen2.5-0.5B-Instruct。冻结 SGLang 提交、模型和 tokenizer 文件摘要。 |
| 请求 | 固定四个 token ID 序列。两个长输入分别为 768、640 token，各生成 16 token。两个短输入分别为 64、96 token，各生成 32 token。并发 2，贪心解码。 |
| 改动 | 原版预填充分块为 512，R01 改为 256。候选意图来自固定输入，SGLang 启停、推理、正确性和计时都在真机上执行。 |
| 接受条件 | 与原版独立采集的 token ID 逐个相同。候选和父版各热身后测 3 轮。吞吐至少增加 5%，首 token 延迟和后续单 token 时延各最多增加 10%。 |
