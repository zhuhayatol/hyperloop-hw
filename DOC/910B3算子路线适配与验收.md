# 910B3 算子路线适配与验收

在 Hyperloop 的同一个算子任务入口接入两条昇腾路线。沿用固定的 Qwen2.5-0.5B-Instruct、四组请求和独立参考输出，候选和父版都先逐 token 校验，再关闭 Profile 进行端到端计时。

## 改了哪些地方

| 位置 | 改动 |
| --- | --- |
| Coordinator 与 RuntimeActions | 真机算子任务要求当前版本的可核验 Profile。按目标配置派发昇腾 GEAK 或 Forge，保存交接和工具交付，随后调用独立评测。 |
| GEAK 执行端 | 识别 Attention 热点，用当前 FIA 设置和反向设置试跑服务，保存两侧的启动身份、输出与计时。候选另开 Profile，确认实际调用了对应的 Attention 实现，交回服务候选。 |
| Forge 执行端 | 用 Profile 定位到 SGLang 的 SwiGLU 调用。受限子进程在 910B3 编译 Triton-Ascend 候选，和 CPU 参考核对两种输入，保存二进制摘要和 NPU 计时，再交回同一份算子源码补丁。 |
| SGLang 执行端 | 在允许路径内将 Forge 补丁装入隔离源码，核对实际加载的文件摘要。固定请求跑过新算子后，记录归属该服务进程的调用标记。 |
| 独立裁决 | 复核 Forge 补丁与工具回执、设备记录和实际调用的绑定，然后与 GEAK 一样，按锁定门槛比较候选、父版和原始基线。 |

GEAK 首版自动搜索的变量是 `ASCEND_USE_FIA`。Forge 首版使用仓库内固定的 SwiGLU 策略。两条真实路线都由代码驱动，复现时使用相同任务配置。候选正确但加速不达标时，工作流可以正常结束并保留父版。

## GEAK 真机验收

会话 G 在提交 `bc87f96` 上完成并以退出码 0 收尾。Kernel Agent 从当前版本的 Profile 交出 Attention 热点。GEAK 用原设置和 FIA 设置各启动一个真实服务，两侧四组输出均正确。另一次采集把候选的 96 条 Prefill `FusedInferAttentionScore` 事件定位到 `ascend_backend.py:1386`，默认设置的 Prefill FlashAttention 定位到同一文件的 1479 行。候选服务配置和工具试跑回执写回 Session。

独立评测重新启动两侧。每侧四组输出逐 token 一致，另有三轮关闭 Profile 的端到端计时。

| --- | ---: | ---: | ---: |
| 吞吐 | 103.55 tok/s | 99.53 tok/s | −3.89% |
| TTFT P95 | 191.05 ms | 222.73 ms | +16.59% |

TTFT 回归超过锁定的 10%，独立裁决 `REVERT / ttft_regression`。Coordinator 保留父版。

## Forge 真机验收

第一次的 Forge 会话 `/opt/f1` 使用提交 `a919708`。重连确认参考采集和基线均通过。隔离账户在线导出 Profile 时，CANN 拒绝其使用开发者账户持有的工具链，留下 222,958,498 字节的不完整 JSON。会话保留父版，算子任务以 `no_usable_profile` 阻断。程序退出码为 0，日志明确记录了 Profile 失败及未执行的任务。

用 CANN 工具链原有账户离线导出同一次采集的副本，获得 239,600,169 字节的 Chrome trace。提交 `4a0178d` 将原始采集与离线导出按权限分开，`c63d012` 支持限定采集窗口。重测 `/opt/f2` 分别采了六个 scheduler 步，两段离线导出均成功，Prefill 和 Decode 各有 144 条 SwiGLU 事件关联 `activation.py:123`。端到端评测仍使用原来的四个请求和性能门槛。

Forge 的隔离 Worker 编译了两个 BF16 形状，两侧均通过 CPU 参考校验。两份候选二进制与真实计时回执已归档，候选在两个形状都更慢。

## 遇到的问题和处理

| 问题 | 处理 |
| --- | --- |
| AMD 原版设备探针在 910B3 上无法通过 | 使用昇腾现有的 SGLang/CANN Profile 和 Triton-Ascend 编译执行。|
| 原真实执行端拒绝带独立算子的版本 | 加入受限的 SwiGLU 补丁加载，只允许指定源文件、版本摘要和隔离账户。 |
| 仅看到 Python 文件被导入，无法确认新算子在请求中运行 | 检查 SGLang 就绪后由实际请求触发的调用标记，同时核对该进程的 launch lease 和文件摘要。 |
| UID 61000 没有系统账户。换成已有的 `nobody` 后，CANN 仍拒绝由非工具链所有者在线导出 | 由隔离账户采集，项目复制同次原始数据，以 CANN 工具链原有账户导出。隔离运行和受保护工具链的权限保持分离。 |
| 无目标配置的旧测试在新路线查配置时报 `KeyError` | 将缺少目标配置视为未启用原生工具，恢复原来的阻断结果。 |
| Windows 普通测试进程未配置包路径，且测试沙箱限制临时文件原子替换 | 用仓库的 `src` 加载本地包，租约顺序测试替换文件写入操作，另在 Linux 真机会话核对实存回执。 |
| 远程裸 SSH 下 `npu-smi` 找不到 CANN 动态库 | 随启动脚本载入固定 CANN 环境后再检查 NPU。 |
| Forge 在进程启动后可能遇到中断或超时 | 启动前写入 Session 租约，保存唯一标记与进程身份，确认已释放设备后再派发后续任务。 |
| 启动预热和 NPU 图捕获也可能调用新算子 | Forge 验收时父版和候选都关掉启动预热与图捕获。确认标记出现在服务就绪后执行的校验请求中。正式计时仍使用固定的两轮请求预热。 |
| SGLang 的 `/health` 会主动生成一个 token，提前消耗调用标记 | Forge 候选的健康检查仅确认服务就绪，把唯一标记留给正式校验请求。 |
| 标记已由真实请求产生，但原检查无法从 `/proc` 的继承标记识别调度进程 | 同时核对它属于这次服务的活动进程组，并且是已记录加载同一补丁文件的进程。 |
| 限定采集步数时，SGLang 自动停止后再次请求停止会返回 HTTP 500 | 记录真实响应，只有同次采集能导出且验证有效时才接受。端到端计时仍使用完整负载。 |
| 最后一次复测的首个归档混入前次复测的启动摘要 | 重新打包对应目录，核对归档摘要，逐项检查复测身份和清理回执。 |
| 默认设置下的 Decode trace 也出现了未关联源码的同名 FIA 事件 | 以 Prefill 设备事件与具体 SGLang 调用点的关联确认切换，并在独立裁决时核对两侧真实启动参数。 |
| CANN 导出日志提示采集调度窗口可能不完整 | 保留告警和原始 trace。验收使用成功导出、可校验摘要并能指向具体调用点的窗口。 |
| Forge 启动后本地 CANNLab 转发于 22:27:47 中断。重连后大归档传输再次断开 | 改用小体积验收归档。大 trace 保留在设备，按路径、字节数和 SHA-256 核实。 |

## 如何使用

在任务里用 `settings.kernel_backend` 选择 `geak` 或 `forge`。在对应 SGLang 目标里启用 `native_geak` 或 `native_forge`，并在任务和目标里启用 Profile。GEAK 需要锁定 `ascend_use_fia` 的默认值。Forge 还需把 `python/sglang/srt/layers/activation.py` 加入目标的源码允许列表，配置低权限试验账户，并提供可用的 Triton-Ascend。

这台 910B3 上 Forge 使用 `sglang.profile.offline_export: true` 和 `sglang.profile.steps: 6`。先通过 CLI 的 `capture-reference` 独立采集参考输出，再以 `run` 启动 Session。要单独复测已登记的候选，可使用 `python -m hyperloop reproduce SESSION CANDIDATE_ID`。报告中的两条路线各自与自己的父版比较。Forge 的父版和候选使用相同的关闭图捕获设置。
